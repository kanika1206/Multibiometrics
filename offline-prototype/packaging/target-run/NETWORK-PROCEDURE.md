# Network/process evidence procedure — target execution required

Perform under local administrator supervision; record and restore policy/adapter state. Do not run this on a remotely accessed-only machine. The scripts are packaging/installation tools, not permission to claim a zero-network pass.

Before the first trial, retain Windows firewall profile/rule export, adapter inventory (including hidden/tunnel adapters), audit-policy backup, process inventory and clock. Configure Windows Filtering Platform connection/drop and process-creation auditing. Start an ETW Winsock/AFD socket lifecycle trace plus process creation/termination and a packet/loopback trace; retain exact provider names/versions and commands. Use locally available Windows netsh/logman/WFP tools or previously staged lab monitoring tools. No installation of monitoring tools during an offline trial.

Validate monitors with a labeled, separate probe BEFORE the trial interval: unconnected socket creation, loopback bind/listen/connect, blocked outbound connect and DNS request. The monitor must identify the probe process and each attempt. WFP blocked events or packet silence alone cannot prove zero socket creation. If sensitivity cannot be demonstrated, STOP the network acceptance condition and record NOT_TESTED; do not infer zero attempts.

Condition A: network interfaces stay enabled. Add outbound block rules for installed Python and codec executables and every child executable discovered during preflight (including system utilities if used). Verify a labeled blocked probe outside the trial interval. Record parent/child lineage, not just static executable names. Start monitoring before candidate launch and continue until all descendants exit. An unexpected child is audited and makes the coverage incomplete until included. Any app/descendant socket event, whether blocked, failed, allowed, loopback or unconnected, is a violation. Attribute unrelated OS traffic with evidence rather than silently excluding it.

Condition B: disable every external adapter/tunnel using the recorded inventory. Use a new evaluation state and repeat the complete lifecycle. Keep socket/process monitoring active; a failed connect on a disabled interface still violates the rule. Do not interpret absence of routable interfaces as absence of attempted sockets.

Keep installer/preflight and lifecycle intervals labeled separately; audit all required operation intervals, not just successful verification. Retain raw traces, WFP event XML, process tree, listener snapshots, rules, adapter states and the attempts ledger. Restore original adapter/firewall/audit settings after collection. Review traces before asserting any condition is passed. No generated development test result substitutes for this procedure.

# Protected Windows template store

## Representation and protection
Keep baseline JSON template payload structure (mean face embedding, frame arrays, voice embedding and metadata); schema resolved from pinned extractTemplate.py: version=2; face.embedding, face.frames, face.n_frames; voice.embedding, voice.model=ecapa-voxceleb, voice.n_samples. No Phase 1 slim migration, cancelable transform or overwrite of v1 data. New three-sample enrollment needs versioned provenance outside/alongside that compatible payload; matcher representation remains baseline-style. Phase 3 may remove unused enrollment arrays only after parity tests.

Proposed Windows mechanism: CurrentUser DPAPI wrapping of independent random 256-bit per-identity AES keys, restricted to the intended Windows account with file ACLs. This does not claim TPM backing or protection from malicious code already running as that user. Do not use machine-wide wrapping by default. TPM-backed protection is an optional separately qualified choice, not an assumed property of DPAPI. OS user/device binding and backup/restore behavior must be measured on the reference build.

AES-256-GCM envelope: fresh unique nonce for each encryption under a key; authenticated metadata includes opaque identity ID, schema version, face/speaker model artifact hashes and enrollment generation. Define deterministic canonical metadata bytes in the future module contract; reject unknown versions. Keep wrapped key and ciphertext generation in one transactional store. Normal logs carry neither keys nor embeddings. Reject invalid tags, swapped identities, incompatible models, malformed dimensions and non-finite payloads.

## Enrollment transaction
Capture three accepted samples and build a provisional template (aggregation in 08). Fresh key and ciphertext remain PENDING; confirmation verification must pass face/voice/challenge against that provisional template before ACTIVE publication. Use durable transaction/atomic generation pointer so crash leaves either no active first enrollment or the complete old/new generation. Do not expose pending identity as enrolled. Plaintext samples and keys have shortest feasible lifetime; do not assert guaranteed RAM erasure in managed runtimes.

## Replacement, recovery and deletion
Re-enrollment requires a fresh full three-factor verification of the existing active identity, a purpose-bound single-use local grant and a new per-user key. Stage new generation, confirm, atomically activate, retire old wrapped key/ciphertext; crash recovery completes retirement without falling back to a stale active generation. First enrollment never silently overwrites an active identity. Deletion atomically marks unavailable and removes template, wrapped key, grants and transient artifacts; clean database journals/checkpoints under the chosen storage lifecycle. No plaintext fallback on failed decrypt or missing key.

Key loss => KEY_UNAVAILABLE / REENROLLMENT_REQUIRED; no authentication possible. Local administrator recovery is documented delete-and-re-enroll, explicitly a trusted-administrator exception, not biometric authentication. Backup policy excludes vault/key material from app-controlled cloud sync. Record OS backup/restore behavior. Key destruction protects leftover ciphertext only if usable old keys/wrappers are unavailable; snapshots, backups and compromised accounts are outside an unconditional erasure guarantee. Local DB encryption/ACLs do not stop rollback by an administrator.

## Privacy and transient media
Normal mode retains no recordings after processing; avoid disk media where possible. If decoder requires private transient files, explicit paths, restrictive ACLs, deletion on success/failure and startup cleanup are required; presence during processing is disclosed. Disable auth-module crash dumps/uploads where controllable and audit actual artifacts. Do not claim no plaintext can ever reach OS paging/hibernation.

Existing evalCapture behavior is an explicit exception: consented evaluation capture retains plaintext recordings. Future research capture is separately enabled, per-attempt consented, local-only, clearly labeled, stored in restricted research directory with retention/deletion policy. No silent production retention; evidence collection must not contradict the disclosed exception.

Tests: swapped identity/version/model metadata, bit flips, truncated ciphertext, corrupt wrapped key, absent key, interrupted initial/re-enrollment transactions at every commit boundary, concurrent deletion/verification, stale grant, backup restore, journal/transient inspection and consent toggles. No active partial enrollment, stale-key fallback or authentication after deletion. Schema source is resolved to pinned HEAD; executable compatibility evidence remains future work.
